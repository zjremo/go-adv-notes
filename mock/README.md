# mock

用 **go.uber.org/mock（MockGen + gomock）** 给接口造替身，用 **testify/assert** 写断言，把「单元测试只测自己的逻辑」这件事落地。

本主题只做两件事：

1. 面向接口编程：`UserService` 依赖 `UserRepo` 接口，而不是具体数据库；
2. 用生成的 mock 替换接口，让测试不碰数据库、不碰网络，并且能**验证调用参数与次数**。

## 目录结构

```text
mock/
├── README.md                     # 本文
└── demo/
    ├── go.mod                    # module golearn/mock
    ├── go.sum
    ├── main.go                   # demo 入口，打印一行
    ├── models/
    │   ├── repo.go               # UserRepo 接口 + User；第 1 行是 go:generate
    │   └── user_service.go       # 被测对象：UserService.GetName
    ├── mocks/
    │   └── repo_mock.go          # mockgen 生成物，不要手改
    └── repo_test.go              # 两个用例：正常返回 / 返回错误
```

依赖：`go.uber.org/mock v0.6.0`（MockGen 与 gomock）、`github.com/stretchr/testify v1.12.1`（assert）。

`go.mod` 里 `go.uber.org/mock` 与 `testify` 都在直接 require 块（`mocks/repo_mock.go`、`repo_test.go` 直接 import 它们）；`go.yaml.in/yaml/v3` 带 `// indirect`，是 testify 传递进来的依赖。

## 为什么需要 mock

被测代码如果直接依赖真实实现，测试就会变成集成测试：慢、需要数据库、难以复现错误分支。把依赖抽成接口后，测试里塞一个「按剧本回答」的替身：

```text
真实链路：UserService → UserRepo → MySQL
测试链路：UserService → MockUserRepo（按 EXPECT 返回固定值）
```

这样能精确控制：

- `GetUser(100)` 返回 `&User{ID:100, Name:"Tom"}`；
- `GetUser(999)` 返回 `errors.New("user not found")`；
- `GetUser` 到底被调用了几次、参数是不是 100。

后两点是「手写空实现」做不到的——gomock 会在测试结束时检查期望是否满足。

## 代码怎么串起来

### 1. 定义接口（`models/repo.go`）

```go
//go:generate mockgen -source=repo.go -destination=../mocks/repo_mock.go -package=mocks
package models

type UserRepo interface {
	GetUser(id int) (*User, error)
}
```

第一行的 `//go:generate` 把「生成命令」写进源码，之后在 `models/` 目录执行 `go generate ./...` 即可重新生成 mock。注意它必须紧贴 `package` 之前、且前面不能空行。

### 2. 被测对象只依赖接口（`models/user_service.go`）

```go
type UserService struct {
	repo UserRepo
}

func NewUserService(r UserRepo) *UserService { return &UserService{repo: r} }

func (s *UserService) GetName(id int) (string, error) {
	u, err := s.repo.GetUser(id)
	if err != nil {
		return "", err
	}
	return u.Name, nil
}
```

构造函数收接口而不是 `*sql.DB`，这是可测性的前提；mock 只是把这个前提兑现。

### 3. 生成 mock（`mocks/repo_mock.go`）

```shell
go install go.uber.org/mock/mockgen@latest   # 一次性安装

cd mock/demo/models
go generate ./...
# 等价于：
# mockgen -source=repo.go -destination=../mocks/repo_mock.go -package=mocks
```

生成的文件头部是 `// Code generated by MockGen. DO NOT EDIT.`，**要入库**（CI 不需要装 mockgen），也不要手动修改——接口一变就重新生成。

生成物里关键的三块：

| 成员 | 作用 |
| --- | --- |
| `NewMockUserRepo(ctrl)` | 构造函数，把 mock 绑定到某个 Controller |
| `EXPECT()` | 进入「录制期望」模式，返回 recorder |
| `GetUser(id int)` | 实现接口；运行时查期望表，命中就返回预设值，没命中直接 `t.Fatalf` |

### 4. 在测试里使用（`repo_test.go`）

```go
func TestUserServiceGetName(t *testing.T) {
	ctrl := gomock.NewController(t)
	defer ctrl.Finish()

	mockRepo := mocks.NewMockUserRepo(ctrl)
	mockRepo.EXPECT().GetUser(100).Return(&models.User{ID: 100, Name: "Tom"}, nil)

	svc := models.NewUserService(mockRepo)
	name, err := svc.GetName(100)

	assert.NoError(t, err)
	assert.Equal(t, "Tom", name)
}
```

四步固定套路：**建 Controller → 造 mock → 录制期望 → 把 mock 注入被测对象**。

`gomock.NewController(t)` 在 v0.6 内部已经用 `t.Cleanup(ctrl.Finish)` 注册了收尾，所以 `defer ctrl.Finish()` 现在是冗余的（保留也无害，老代码常见）。

## gomock 常用 API

| API | 说明 |
| --- | --- |
| `EXPECT().Method(args...)` | 录制一次调用期望，返回 `*gomock.Call` |
| `.Return(v1, v2)` | 命中后期望的返回值，顺序与函数签名一致 |
| `.Times(n)` | 调用次数；不写默认 `Exactly(1)` |
| `.AnyTimes()` | 0 次或多次都可以 |
| `.MinTimes(n)` / `.MaxTimes(n)` | 次数区间 |
| `.Do(func(args...)) ` | 命中时执行副作用（记录参数、改状态） |
| `.DoAndReturn(fn)` | 用函数动态计算返回值 |
| `gomock.Any()` | 参数匹配任意值 |
| `gomock.Eq(v)` | 显式「等于」（直接传值本来就是 Eq） |
| `gomock.InOrder(c1, c2)` | 强制调用顺序 |
| `gomock.Anything` | 占位符，配 `Do`/`Any` 时常用 |

默认 `Times(1)` 是新手最容易踩的点：被测代码多调一次、少调一次，测试都会在 `Finish` 时报 `missing call` / `unexpected call`。

## testify/assert 用法

| 断言 | 语义 |
| --- | --- |
| `assert.NoError(t, err)` | err 为 nil，失败继续执行 |
| `assert.ErrorContains(t, err, "user not found")` | err 非 nil 且包含子串 |
| `assert.Equal(t, want, got)` | 深度相等，失败打印 diff |
| `assert.Empty(t, name)` | 空字符串/空切片/空 map 都算空 |
| `require.*` | 与 assert 同名，但失败立刻 `FailNow` |

第二条用例演示了错误分支：

```go
mockRepo.EXPECT().
	GetUser(999).
	Return(nil, errors.New("user not found"))

name, err := svc.GetName(999)

assert.ErrorContains(t, err, "user not found")
assert.Empty(t, name)
```

选择原则：**参数/前置条件用 require，结果断言用 assert**。前置失败后继续断言只会刷屏。

## 常见坑

1. 期望参数必须能匹配：`EXPECT().GetUser(100)` 遇到实际调用 `GetUser(999)` 会立刻报 `unexpected call`，不是返回零值。
2. 忘记写 `EXPECT()` 就直接调用 mock 方法 → 运行期 `t.Fatalf("missing call")`。
3. 默认只允许调用一次；循环/重试场景要 `.Times(n)` 或 `.AnyTimes()`。
4. `Return` 的类型必须与接口签名一致，生成物内部是类型断言，对不上会 panic。
5. 生成物与接口不同步（改了接口没重新 `go generate`）→ 编译报「does not implement」。
6. mock 只该出现在测试/测试辅助包；生产代码 import `mocks` 说明依赖方向反了。
7. 不要 mock 值对象或纯函数——直接造真实值更简单；mock 的成本来自「验证交互」，没有交互要验证就别 mock。

## 与手写 stub 的取舍

| | 手写 stub | gomock |
| --- | --- | --- |
| 成本 | 每个接口手写一个 struct | 一条命令生成 |
| 验证调用次数/参数 | 自己记录 | 内建 |
| 可读性 | 逻辑透明 | EXPECT 剧本式，一眼看出依赖行为 |
| 接口多时 | 维护量大 | 生成物自动同步 |

## 运行

```shell
# 跑 mock demo 的测试（不需要数据库/网络）
go test ./mock/demo/... -v

# 只跑本模块
cd mock/demo && go test ./... -v

# 重新生成 mock（在 models 目录）
cd mock/demo/models && go generate ./...
```
